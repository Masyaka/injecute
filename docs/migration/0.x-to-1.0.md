# Migrating from 0.x to 1.0

injecute 1.0 cleans up the public API. This page lists every breaking change with a before/after example.
Work through it top to bottom; most changes are mechanical.

## Module format: ESM only

1.0 ships a single ES module build. The CommonJS build is gone.

- **Node.js ≥ 22** is required. `require('injecute')` keeps working through Node's `require(esm)` support.
- Browsers, Deno and Bun import the package directly, including from CDNs such as esm.sh and jsDelivr.
- Bundlers need no configuration.

```ts
// before (CommonJS)
const { DIContainer } = require('injecute');

// after (ESM)
import { DIContainer } from 'injecute';

// still works on Node ≥ 22 (require of an ES module)
const { DIContainer } = require('injecute');
```

## The `utils` object is removed

Every helper was already exported by name. The grouped `utils` object duplicated them and broke the
published type declarations for projects with `skipLibCheck: false`.

```ts
// before
import { utils } from 'injecute';
utils.construct(MyClass);

// after
import { construct } from 'injecute';
construct(MyClass);
```

## `null` and `undefined` are valid service values

0.x treated a factory result of `null` or `undefined` as "not registered": `get()` threw
`No service registered`, and singletons returning `null` ran their factory again. 1.0 looks services up by
key, so any value, including `null` and `undefined`, is returned and cached.

```ts
const c = new DIContainer().addSingleton('session', () => null, []);
c.get('session'); // 0.x: throws · 1.0: null
```

## Decorating a service with a self dependency

A dependency on the key being registered now resolves the **previous definition** of that key: the
replaced one in the same container (with `replace: true`), or the parent's one in a child. In 0.x a child
could not do this at all.

```ts
const child = parent
  .fork()
  .addSingleton('logger', (logger) => withPrefix(logger), ['logger']);
```

Re-registering an own key without `replace: true` throws `already registered` (0.x threw
`CircularDependencyError` when the new registration depended on itself).

## Middlewares run once per `get()`

In 0.x a fork copied its parent's middlewares, and resolving a parent service ran them again at every
level, so one `get()` through two forks ran a middleware three times. 1.0 runs the chain once per `get()`.

## Middleware signature: `(key, next, context)`

Middlewares no longer receive the container as `this`, so arrow functions work. The container and the
resolution path are on the third argument. `next()` continues with the same key; `next(otherKey)`
resolves another key.

```ts
// before
container.use(function (key, next) {
  this.get('logger').debug(String(key));
  return next(key);
});

// after
container.use((key, next, { container, path }) => {
  container.get('logger').debug(path.join(' > '));
  return next();
});
```

Forks inherit their ancestors' middlewares **live**: a middleware added to a parent after `fork()` applies
to existing forks. `fork({ skipResolvers: true })` is now `fork({ middlewares: false })`. Remove a
middleware with `unuse(middleware)`.

## `flatten()` is removed

`flatten()` threw with its default options and, when forced to run, cached the flattened container's
singletons in the root container. Use an isolated fork instead: it runs every factory it resolves in the
fork, so overrides reach the whole graph and nothing leaks back.

```ts
// before
const copy = app.flatten({ onKeyIntersection: (k) => () => undefined });

// after
const copy = app.fork({ isolated: true });
```

## Introspection: `getRegistration()` replaces `getFactory()`

`getFactory()`, `entryTypeKey`, `firstResult` and the `EntryType` type are removed. Read registration
metadata with `getRegistration(key)`, which returns a read-only `RegistrationInfo` (`kind`,
`dependencies`, `target`, `namespace`, `depth`). `EntryType` is now `RegistrationKind`.

The `replace` event payload reports the replaced registration as `previous: RegistrationInfo` instead of
`replaced: { callable, type }`.

## Registration hooks are removed

The undocumented `beforeResolving`, `afterResolving` and `beforeReplaced` registration options are gone.
Use the `produce` / `replace` events or a middleware instead.

## Container roles: `ServiceProvider`, `ServiceRegistry`, `DIContainer`

1.0 splits the container into three levels. Each piece of code gets only what it needs:

| Type                 | Can                                                                                             | Give it to                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `ServiceProvider<S>` | resolve (`get`, `has`, `createResolver`, `call`) and inspect (`keys`, `getRegistration`)        | handlers and other consumers, middleware context, event payloads |
| `ServiceRegistry<S>` | everything above, plus register (`add*`, `addAlias`, `namespace`, `extend`, `injecute`, `bind`) | module / extension functions                                     |
| `DIContainer<S>`     | everything above, plus `use`/`unuse`, events, `fork`, `reset`, `dispose`                        | the composition root                                             |

- `IDIContainer<S>` still exists as a deprecated alias of `ServiceRegistry<S>`.
- The chain keeps its type: `new DIContainer().addInstance(…).use(…)` compiles (0.x lost `use()` after
  the first `add*`).
- `get('SomeNamespace')`, `getParent()` and the middleware/event `container` are read-only providers.
- `DIContainer<TOwn, TParent>` has one type parameter now: `DIContainer<S>`.

Modules no longer need to be generic. Declare only what the module needs and apply it with `extend()`:

```ts
// before
const addBilling = <T extends { db: Database }>(c: IDIContainer<T>) =>
  c.addSingleton('invoices', construct(InvoiceRepository), ['db']);

// after
const addBilling = (c: ServiceRegistry<{ db: Database }>) =>
  c.addSingleton('invoices', InvoiceRepository, ['db']);

app.extend(addBilling); // type error if `db` is not registered
```

## Classes are registered directly

Classes are detected and constructed with `new`; `construct()` is optional.

```ts
// before
app.addSingleton('users', construct(UserRepository), ['db']);

// after
app.addSingleton('users', UserRepository, ['db']);
```

Keep `construct()` for classes compiled to ES5 (Babel for old browsers, TypeScript `target: es5`) and bound
classes: they look like plain functions and cannot be detected.

## Optional dependencies: `optional(key)`

The magic `'undefined'` dependency key is gone (and `'undefined'` is an ordinary key now). Use
`optional(key)` for "the service if it is registered", or a function dependency for a fixed value.

```ts
// before
app.addSingleton('mailer', construct(Mailer), ['undefined']);

// after
app.addSingleton('mailer', Mailer, [optional('transport')]);
app.addSingleton('mailer', Mailer, [() => undefined]);
```

## Renamed options and removed constructor argument

| 0.x                                            | 1.0                                                    |
| ---------------------------------------------- | ------------------------------------------------------ |
| `get(key, { allowUnresolved: true })`          | `get(key, { optional: true })`                         |
| `has(key, false)`                              | `has(key, { local: true })`                            |
| `new DIContainer({ parentContainer: parent })` | `parent.fork()`                                        |
| `createProxyAccessor(c, { allowUnresolved })`  | `createProxyAccessor(c, { optional })`                 |
| `import DIContainer from 'injecute'`           | `import { DIContainer } from 'injecute'`               |
| `ArgumentsKey`                                 | `ServiceKey` (deprecated alias kept)                   |
| `DependenciesToTypes<Keys, S>`                 | `ResolveDependencies<Keys, S>` (deprecated alias kept) |
| `Events<C>`                                    | `ContainerEvents`                                      |

`createProxyAccessor()` objects now support `in`, `Object.keys()` and spreading; writes throw
`The proxy accessor is read-only.`

## Removed type exports

These helper types are gone; most were internal or unused: `Callable`, `Func`, `Constructor`,
`CallableResult`, `ValueOf`, `Empty`, `Flatten`, `Merge`, `KeyForValueOfType`, `ValuesOfType`,
`ArgumentsTypes`, `Dependencies`, `TypesToKeys`, `PromisedProperties`, `CallableOf`, `ArgumentsResolver`,
`InjecuteOptions`, `WithNamespace`, `MapOf`, `ResolversMapKeys`, `Resolve`, `Resolver`,
`IDIContainerExtension`, `ContainerOwnServices`, `ContainerParentServices`,
`DIContainerConstructorArguments`, `OptionalDependencySkipKey` and `optionalDependencySkipKey`.

Use `Factory<D, S>`, `Produced<F>`, `ResolveDependencies<D, S>`, `ContainerServices<C>` and the option
types (`SingletonOptions`, `InstanceOptions`, `ForkOptions`, …) instead. A module function is simply
`(c: ServiceRegistry<{ … }>) => …`.
